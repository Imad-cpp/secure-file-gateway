# Secure File Gateway v1.0.0 — Release Notes

> **Release status:** prepared release notes. The `v1.0.0` tag and GitHub release do not exist yet. They must only be created after the exact release commit passes the final Definition-of-Done audit and post-merge `Application Quality` gate.

## What V1 demonstrates

Secure File Gateway is a security-focused Laravel API that treats every uploaded object as untrusted until server-side validation, quarantine handling and asynchronous malware scanning succeed.

The V1 portfolio boundary demonstrates:

- bearer-token authentication and owner-scoped object authorization;
- private quarantine and private clean object-storage zones;
- extension and server-detected MIME agreement;
- SHA-256 integrity metadata and owner-scoped duplicate protection;
- Redis-backed asynchronous scanning;
- ClamAV `INSTREAM` integration behind an application scanner interface;
- fail-closed lifecycle transitions;
- short-lived signed application capabilities for controlled delivery;
- deletion-driven capability revocation and targeted cleanup retry;
- request correlation and sanitized security audit events;
- concrete dependency readiness checks;
- machine-checked OpenAPI route coverage;
- reproducible local/container infrastructure and CI evidence.

## Core lifecycle

```text
QUARANTINED → SCANNING → AVAILABLE
                  ├────→ REJECTED
                  └────→ SCAN_FAILED

QUARANTINED / SCANNING / AVAILABLE / REJECTED / SCAN_FAILED
                         ↓
                      DELETED
```

Clients cannot mark a file clean or available. `AVAILABLE` is reached only after the application accepts a clean scanner result and successfully promotes bytes into private clean storage.

## Public V1 API

```text
POST   /api/v1/auth/register
POST   /api/v1/auth/login
POST   /api/v1/auth/logout
GET    /api/v1/me

POST   /api/v1/files
GET    /api/v1/files
GET    /api/v1/files/{file}
POST   /api/v1/files/{file}/download
DELETE /api/v1/files/{file}

GET    /api/v1/files/{file}/content

GET    /health/live
GET    /health/ready
```

The signed-content endpoint is a temporary capability route rather than a normal bearer-authenticated metadata read. It validates signature, expiry and current `AVAILABLE` state before private bytes are streamed.

## V1 file policy

| Type | Extensions | Server-detected MIME | Maximum size |
|---|---|---|---:|
| PDF | `.pdf` | `application/pdf` | 10 MiB |
| PNG | `.png` | `image/png` | 10 MiB |
| JPEG | `.jpg`, `.jpeg` | `image/jpeg` | 10 MiB |
| Plain text | `.txt` | `text/plain` | 10 MiB |

The intentionally narrow allowlist limits attack surface. Adding more content types requires explicit review and tests.

## Security properties evidenced in V1

- Original filenames are display metadata only and never become object keys.
- Quarantine objects are not directly downloadable.
- Client-declared MIME is not trusted.
- Unsafe results never enter clean storage.
- Scanner errors fail closed.
- File metadata reads, deletion and capability issuance are owner-authorized.
- Duplicate detection is owner-scoped to avoid a cross-user file-presence oracle.
- Signed URLs are short lived and become unusable after deletion because content delivery re-checks lifecycle state.
- Request IDs are generated by the server rather than accepted from clients.
- Audit metadata is bounded and sanitized to exclude sensitive values such as credentials, bearer tokens, signatures, signed URLs, file bodies and private object keys.

## Reproducible evidence

The permanent `Application Quality` workflow checks three independent boundaries:

1. **`php-quality`** — strict Composer lock validation/install, Pint, Larastan/PHPStan level 5 without a baseline, automated tests including OpenAPI route-drift checks, and Composer audit.
2. **`secret-hygiene`** — full-history Gitleaks scanning with read-only workflow permissions.
3. **`infrastructure-integration`** — real Dockerized Laravel/PostgreSQL/Redis/MinIO/ClamAV topology, migrations, aggregate readiness, Redis scan worker, real clean + runtime-generated EICAR application paths, and the same reproducible public demo documented for contributors.

The clean real-engine path must reach `AVAILABLE`, issue a temporary signed capability, stream byte-identical content and delete successfully. The EICAR antivirus test fixture must reach `REJECTED` and remain non-downloadable.

The reproducible normal-user demo performs:

```text
register → login → upload → poll → AVAILABLE → signed download → byte compare → delete
```

See `docs/V1_DEMO.md` and `docs/V1_EVIDENCE.md` for the executable steps and evidence boundaries.

## Deliberate V1 boundaries

This release does **not** claim:

- production readiness or production availability guarantees;
- malware-detection completeness or arbitrary-file safety;
- production monitoring or incident-response maturity;
- a transactional or immutable forensic audit ledger;
- generic bucket-wide orphan discovery;
- performance or scale benchmarks.

V1 also deliberately excludes public sharing, anonymous uploads, archive extraction, remote URL ingestion, document conversion, preview generation, collaborative folders, microservices, Kubernetes and AI features.
